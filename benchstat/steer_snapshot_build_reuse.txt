Post-backoff optimization round (working tree after b7ca96b), 2026-07-22.
Same machine/go as backoff_e2e.txt (Ryzen 9 7900, go1.26.2), count=6 x2 runs
combined, benchtime=1s, -benchmem. Baseline = HEAD b7ca96b via git worktree.

Changes, in order of impact:
1. interned/backoff.go steering: replace the per-candidate order-MaxVerbatim
   table probe with ONE lookup per step of the order-(MaxVerbatim-1) table.
   That entry's follower set is exactly the set of tokens completing a
   verbatim MaxVerbatim-gram, so steering becomes a membership test: == for
   the ~98% of steering states with one follower, a <=16 linear scan for
   the rest, per-candidate probes only for high-fanout states (steerBig
   fallback). End is excluded explicitly (End appears in follower sets but
   never in an order-R state, preserving "End can never be filtered").
   Steered gen micro: 3105ms -> 90ms per 10k gens (-97%, ~34x); steered is
   now within ~0-5% of plain. Semantics pinned by the existing steering
   tests + TestSteeringOracle (1000 sentences, zero verbatim 6-grams).
2. interned build: the transient state table IS the final Model now. The
   corpus scan stores the dense obs index in each slot's ChoicesIndex
   (Offset=idx+1); the grouping pass overwrites slots in place via
   stateMap.forEach. Kills the separate rehash+insert pass and its
   allocation. Table sizing uses measured states/obs ratios per order
   (0.10/0.45/0.75/0.85 for N=1/2/3/4+) instead of obs+64.
   BuildIndexedByN: -39%..-60% sec, -53%..-63% B/op.
3. barkov.Gen fast path: with no options and a non-cancellable ctx, Gen
   skips the iter.Seq2 machinery and walks MoveKey in a plain loop (same
   MoveKey/RNG sequence, same output). GenHeavyInterned: -27% sec,
   -62% B/op, -72% allocs/op.
4. interned/statemap.go: inline multiply-xorshift lane mixer replaces
   maphash.Comparable (per-map random seed kept). sizeof(K) is a per-
   instantiation constant, so the mixer is straight-line code. Probe
   geometry on the N=4 public-corpus table: avg 0.55, p99 fine at load
   0.525 (measured pre-merge).
5. Adaptive <=16-linear / >16-binary cumdist scan in indexedCore.pickFollow,
   CompressedChain.Move, backoffCore.draw (was sort.Search everywhere /
   linear-only in draw).
6. buildBackoffCore builds the per-order tables concurrently (independent
   builds, corpus read-only). Together with #2 this takes e2e backoff build
   from ~1.0s to ~0.23-0.27s (-76%..-78%) and cuts B/op -56%.

String Tier-1 path: unchanged. First measurement round showed phantom
+28..+75% regressions on string/* e2e; reverse-order rerun made them
insignificant (p>=0.06) and interleaved A/B runs of prebuilt binaries on
string/FNV + string/XXH3 show p=0.886 — thermal ordering drift, not code.
PipelineSimpleVsMaxOpt/simple: p=0.932 flat.

Full test suite green, including -race on ., ./interned, ./text.
